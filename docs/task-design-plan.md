# Task 1 与 Task 2 设计及实验计划

这份文档用于说明项目准备做什么、为什么这样设计，以及后续实现顺序。算法和实验配置是本项目方案，不是作业指定的唯一做法；参数目前是起始值，实际效果需要实验验证。

## 1. 两个任务分别做什么

| 项目 | Task 1：天气分类 | Task 2：评论评分预测 |
|---|---|---|
| 输入 | 每条记录的 10 个属性 | 标题、正文、用户、商品、时间等信息 |
| 目标 | 预测天气类别：1 晴、2 多云、3 雨、4 雪 | 预测评论的 1–5 分评分 |
| 主指标 | Macro-F1，越高越好 | RMSE，越低越好 |
| 主模型 | 自己实现的 CART 决策树和随机森林 | 自己实现的稀疏线性回归模型 |
| 计算方式 | 普通单机训练 | Spark 并行处理和分布式梯度训练 |
| 提交文件 | 两列：`id,label` | 两列：`id,rating` |

共同输入是 `train.csv`、`test.csv` 和 `sample_submission.csv`。Task 2 必须使用大数据并行/分布式框架；Task 1 没有这个强制要求。第三方库可以做数值运算和数据处理，但需要展示自主算法设计，不能只调用现成预测模型。

## 2. 整体功能与模块分工

```text
命令行 CLI
    ↓ 读取 JSON 配置，根据 task 选择任务
任务 pipeline
    ↓ 调用各模块，组织执行顺序
数据 → 特征 → 模型 → 评估/预测 → 保存结果/导出 CSV
```

| 模块 | 功能 |
|---|---|
| `cli.py` | 明确列出每个命令及参数，调用对应函数 |
| `common/config.py` | 读取 JSON，配置内相对路径以 JSON 所在目录为基准 |
| `common/contracts.py` | 统一配置、评估结果、模型包等数据结构 |
| `common/reproducibility.py` | 随机种子与运行清单 |
| `common/benchmark.py` | 硬件信息、预处理/训练/推理耗时 |
| `common/artifacts.py` | 保存模型状态、运行指标，恢复模型包 |
| `common/metrics.py` | 自主计算 Macro-F1、RMSE |
| `common/submission.py` | Task 1 的通用 CSV 校验和导出 |
| `task1/`、`task2/` | 各任务的数据、特征、模型、预测与流程 |
| `experiments.py` | 基线实验、消融实验、并行度实验及报告表格 |

代码保持直接、易读。CLI 的命令和参数逐项声明；配置按可信输入处理，不增加复杂异常包装。数据清洗、训练/验证隔离、预测 ID 对齐等属于任务正确性，仍要在对应业务模块实现。

## 3. 统一的三条执行流程

### 3.1 验证实验：选择方案

`train.csv → 固定训练/验证划分 → 训练折拟合特征 → 训练模型 → 验证指标`

- 初始验证比例为 20%，种子为 5434，保存实际划分，后续方案共用它。
- 缺失填充值、类别编码、IDF、统计特征只能从训练折学习。
- 验证集用于选参数及早停，不参与特征拟合；不使用测试标签。
- 保存配置、指标、硬件、耗时，便于比较及写报告。

### 3.2 最终训练：生成正式模型

`锁定模型和参数 → 全量 train.csv 拟合特征和模型 → 保存完整模型包`

- 不再重新搜索参数；Task 2 使用验证阶段选定的 epoch。
- 全量重训后不能再把原验证集分数当作独立验证成绩。
- 模型包必须同时保存模型参数和预处理状态。

### 3.3 预测：生成 Kaggle 提交

`恢复模型包 → 读取 test.csv → 特征转换 → 预测 → 按样例导出 CSV`

- 不重新训练、不重新拟合编码器或 IDF。
- 模型和特征使用训练时保存的参数；测试 ID 与预测一一对应。
- 按提交样例的列名和 ID 顺序输出，不导出额外索引列。

## 4. Task 1 具体设计

### 4.1 数据与特征

- 检查 10 个属性的实际类型、缺失、重复、异常值和类别分布；不预设未知属性的含义。
- 数值缺失用训练折中位数填补；类别缺失、未见类别使用明确的编码。
- 可增加“该属性是否缺失”的特征，实验判断是否有帮助。
- `id` 用于记录对齐，不作为数值特征；`label` 只作为训练目标。
- 使用分组分层划分：尽量保持类别比例，相同/重复记录放入同一组，避免跨集合泄漏。

### 4.2 模型与自主实现内容

1. **多数类基线**：所有记录预测为训练折中最多的类别，提供最低比较标准。
2. **自定义 CART 决策树**：实现 Gini、不纯度下降、候选分裂、停止条件和叶节点概率。
3. **自定义随机森林**：实现 bootstrap 抽样、随机子特征、多棵树训练和概率平均。

类别概率顺序固定为 `[1,2,3,4]`。类别权重用于改善少数类表现，最终取决于 Macro-F1。

### 4.3 已设计的实验

| 实验 | 比较内容 | 想回答的问题 |
|---|---|---|
| 基线比较 | 多数类、单棵树、随机森林 | 自定义模型是否有效？多树是否优于单树？ |
| 类别权重消融 | `balanced` 与不加权 | 是否改善少数类和 Macro-F1？ |
| 缺失指示消融 | 开启与关闭 | 缺失情况本身是否有预测价值？ |
| 参数比较 | 树数量、最大深度、最小叶样本数、子特征数 | 如何平衡过拟合、效果和训练成本？ |
| 类别误差分析 | 逐类 precision/recall/F1、混淆矩阵 | 哪类天气最容易预测错？ |
| 稳定性检查 | 对入选方案使用多个种子或交叉验证，资源允许时做 | 提升是否稳定？ |

起始配置：100 棵树、最大深度 12、叶节点至少 5 个样本、开启类别权重及缺失指示。参数比较不需要穷举所有组合，先筛选再小范围调整。

### 4.4 模块职责

| 文件 | 职责 |
|---|---|
| `data.py` | 读取、数据审计、固定划分 |
| `features.py` | 特征拟合、转换及状态恢复 |
| `model.py` | 自定义树和森林 |
| `training.py` | `evaluate_candidate()` 做验证；`fit_final()` 做全量重训 |
| `submission.py` | 天气提交文件出口，复用公共导出逻辑 |
| `pipeline.py` | 调用训练接口；恢复模型、预测、记录运行结果 |

Task 1 模型包状态约定为 `params`、`preprocessor`、`model`，供训练保存与预测恢复共同使用。

## 5. Task 2 具体设计

### 5.1 数据与划分

- Spark 读取评论，支持评论中的引号、逗号和换行，ID 保持字符串。
- 检查空文本、缺失字段、重复评论、评分分布及用户/商品数量。
- 主实验使用稳定哈希分组划分，固定 seed；重复评论不跨训练/验证集合。
- 可补充时间划分作为泛化诊断，不预先假定测试集一定按时间生成。

### 5.2 特征

| 特征组 | 计划内容 |
|---|---|
| 标题 | 规范化、分词、可选 n-gram、哈希词频和 IDF |
| 正文 | 同上，与标题使用独立哈希空间 |
| 数值/类别信息 | 购买标记、`log1p(votes)`、文本长度等 |
| 用户/商品信息 | 训练中的用户、商品、父商品频率等统计 |
| 时间信息 | 确认时间单位及数据含义后，再设计时间特征 |
| 可选目标编码 | 用户/商品平均评分，必须使用折外统计 |

标题和正文初始各 65536 维，再追加元数据，保存完整特征布局。使用稳定哈希，确保不同进程得到相同索引；不把用户/商品 ID 直接当连续数值。

目标编码默认关闭。开启时，训练行的编码不能包含自身标签；验证/测试使用训练折统计，未知用户/商品回退到训练先验。全量重训也遵守这个规则。

### 5.3 模型与 Spark 的作用

1. **全局均值基线**：所有评论预测为训练折平均评分。
2. **文本基线**：只用文本特征，训练自定义回归模型。
3. **主方案**：文本与元数据组合，训练自定义稀疏线性回归，优化平方损失并加 L2 正则。

每轮训练按固定规则分小批次：

```text
driver 广播当前权重
    → 各分区并行计算梯度和、误差和、样本数
    → 汇总全局梯度
    → 按总样本数归一化，加一次正则，更新参数
```

自主实现分词/哈希、预测计算、梯度、聚合和参数更新；Spark 负责数据分区及并行执行，不直接调用现成预测器。

缓存编码结果，避免每轮重新处理文本；及时释放广播和缓存。只收集受控大小的参数、梯度及标量统计，不把全量评论或预测 `collect()` 到 driver。

训练记录每个 epoch 的耗时、损失和验证 RMSE；早停后恢复最佳参数。预测可保留小数，不默认四舍五入；是否裁剪到 `[1,5]` 通过验证比较。

### 5.4 已设计的实验

| 实验 | 比较内容 | 想回答的问题 |
|---|---|---|
| 基线比较 | 全局均值、纯文本、文本+元数据 | 模型和附加信息各带来多少提升？ |
| 标题消融 | 完整模型与去掉标题 | 标题是否提供额外信息？ |
| 正文消融 | 完整模型与去掉正文 | 正文贡献有多大？ |
| 元数据消融 | 完整模型与去掉元数据 | 用户/商品等信息是否有效？ |
| IDF 消融 | 开启与关闭 | 降低高频词权重是否有帮助？ |
| 参数比较 | 哈希维数、学习率、L2、epoch、批次数 | 如何平衡精度、碰撞、内存和耗时？ |
| 评分裁剪 | 原始输出与裁剪到 `[1,5]` | 裁剪能否降低 RMSE？ |
| 冷启动分析 | 已见/未见用户、已见/未见商品 | 新用户或商品上的表现如何？ |
| 误差分析 | 按真实评分、文本长度分组，报告组内样本数 | 哪些评论难预测？ |
| 并行度实验 | 1、2、4、8 个可用线程等 | Spark 并行是否真正提速？ |
| 补充诊断 | 去掉 votes、时间划分、多种子；目标编码开关如实现 | 是否存在时点依赖，提升是否可靠？ |

起始配置：20 epoch、每轮 4 批、学习率 0.01、L2 为 0.0001、早停等待 3 轮；仅作为初始实验值。

消融每次只改变一个因素，其他条件保持一致。并行度实验固定数据、特征、epoch、批次和缓存口径，改变实际 Spark 资源并记录；不能只修改一个没有生效的配置。加速比为 `单线程耗时 / 当前耗时`，同时检查 RMSE 是否有明显变化。

### 5.5 模块职责

| 文件 | 职责 |
|---|---|
| `spark_runtime.py` | 创建/关闭 Spark，记录实际资源 |
| `data.py` | 分布式读取、审计、划分 |
| `features.py` | 特征拟合、训练转换、预测转换和状态保存 |
| `optimization.py` | 分区梯度、汇总及全局参数更新 |

| `submission.py` | 按样例 ID 流式导出单个 CSV |

## 6. 实验记录、复现与计时

每次运行使用独立目录：`runs/<task>/<阶段>-<运行ID>/`。计划保存：

- 任务配置与随机种子；依赖版本由项目依赖锁文件管理。
- 训练/验证划分、数据审计、指标、epoch 日志。
- CPU 型号、服务器/线程数量、内存、GPU（如使用），Task 2 的实际 Spark 资源。
- 模型、预处理状态、特征映射/布局、提交 CSV。

计时口径：

| 阶段 | 记录内容 |
|---|---|
| 验证实验 | 数据处理、训练和最终验证评估 |
| Task 1 最终训练 | 委托 `fit_final()` 的总时间，当前包含模型保存 |
| Task 2 最终训练 | 读取/审计/预处理+训练；保存另计，Spark 启动不计入 |
| 每 epoch | Task 2 模型内部记录；Task 1 无 epoch，说明 N/A，可报告每树耗时 |
| 全测试推理 | 模型恢复、读取、特征转换和全部预测；Task 2 需触发实际计算 |
| CSV 导出 | 单独计时，避免与推理时间混淆 |

以上子阶段可能包含重叠，不能直接相加代替端到端时间。Spark 需要实际 action 才能说明计算已经完成。不同配置采用一致的冷热缓存口径。

正式提交前，在新进程恢复模型并重新生成预测，核对 ID、行数和预测结果。分布式浮点归约可能有小差异，应明确容差，不承诺任意硬件完全逐位一致。

## 8. 当前进度与后续顺序

| 状态 | 内容 |
|---|---|
| 已实现 | CLI、命令入口、JSON 配置读取、两个 pipeline 的流程编排 |
| 已验证 | 配置读取、CLI 分发、pipeline 调用及 Spark 释放逻辑的流程测试 |
| 尚未实现 | 数据、特征、算法、优化器、指标、计时、状态保存等依赖模块，以及实验批量执行与表格汇总 |
| 尚未完成 | 真实数据训练、效果/效率实验、正式预测、报告和展示 |

流程测试使用依赖替身，不代表真实模型或 Spark 作业已运行。现在执行训练命令，仍会在尚未实现的依赖处抛出 `NotImplementedError`。

建议实现顺序：

1. 公共工具：种子/运行清单、指标、计时、模型保存及 CSV 导出。
2. Task 1：数据 → 特征 → 单树 → 森林 → training，跑通验证和预测。
3. Task 2：Spark/数据 → 特征 → 梯度更新 → 模型 → 评估/导出，跑通验证和预测。
4. 实现基线、消融、参数比较、并行度实验及报告表格。
5. 锁定方案，完整重训，新进程复现预测，再提交 Kaggle。
6. 根据实测结果完成报告、幻灯片和最终打包。

已知接口限制：Task 1 预测调用的 `WeatherDataset.load()` 同时读取训练和测试文件，所以暂时仍需要训练文件存在，但不会重新训练。Task 2 预测只读取测试数据。
